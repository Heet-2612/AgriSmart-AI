# Implementation Plan: Bonus Module C — Weather-Based Intelligence

## 1. Module Purpose

**Weather-Based Intelligence** is an agricultural decision-support module within AgriSmart AI. It pairs real-time atmospheric conditions and short-term forecasts from Open-Meteo with farmer-provided field context (crop type, growth stage, and optional soil moisture) to produce actionable, timely, and deterministic agricultural advisories.

### Explicit Operational Boundaries
* **Deterministic Rule-Based Decision Support:** This feature operates strictly on explicit agronomic logic, meteorological thresholds, and rule trees. It does **not** employ artificial intelligence, machine learning forecasting models, or black-box predictive algorithms.
* **Non-Expert Advisory Disclaimer:** Advisories generated by this module are intended solely for operational decision-support and risk-awareness. They do **not** constitute certified professional agronomic advice, official meteorological alerts, or localized microclimate guarantees. Farmers must verify advisories against local field observations and regional agricultural extension guidelines.

---

## 2. MVP Scope

The Version 1 (MVP) implementation is designed as a **frontend-only, lightweight, client-side web application** integrating public APIs directly without backend overhead.

### Technical Stack
* **UI Framework:** React 19 (Functional Components, Hooks)
* **Language:** TypeScript 5.x (Strict typing, interface definitions)
* **Build Tooling & Dev Server:** Vite 7.x
* **Styling & Layout:** Tailwind CSS 4.x (Responsive utility classes, CSS variables)
* **Async State & Cache Management:** TanStack Query 5.x (`@tanstack/react-query`)

### MVP Architectural Exclusions (Version 1)
* **No FastAPI / Backend Proxy Required:** Client directly queries public Open-Meteo endpoints.
* **No Database / Persistence Layer:** In-memory client caching via TanStack Query and optional `localStorage` for farm profile preferences.
* **No Authentication / User Accounts:** Zero friction for hackathon demo and immediate field trial.
* **No Machine Learning Models:** Zero model checkpoints, weights, or Python runtime dependencies.
* **No IoT / Sensor Hardware:** Does not require connected weather stations or telemetry probes.
* **No API Key Requirement:** Open-Meteo provides free, keyless open access for non-commercial and hackathon tiers.

## 3. Inputs

The module consumes two categories of inputs: **User Farm Context** and **Meteorological Data**.

### A. User Farm Context Inputs
| Field Name | Type | Permissible Values / Range | Default Value | Mandatory? | Purpose |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Location / City** | Text | Valid geocodable query (e.g. `Pune`, `Nashik`, `Nagpur`) | `Pune` | **Yes** | Geocoded to lat/lon coordinates for weather retrieval |

* **Next-24-Hour Forecast Data:** Hourly and daily aggregated meteorological variables covering the immediate 24-hour operational window.

## 4. Data-Source & Data-Type Disclosure

Transparency is paramount to prevent misleading farmers about the origin and freshness of weather data.

### Data Categories & Definitions
1. **Live / Current Conditions:** Retrieved at request time from Open-Meteo models. Reflects near-real-time model reanalysis and surface observations.
2. **Forecast Data:** Projected meteorological conditions over the next 24 hours provided by Open-Meteo weather models.
3. **Historical Data:** **Not used** in Version 1 MVP.
4. **Simulated Demo Data:** Explicitly labeled fallback scenario (e.g., standard Pune demo conditions) used solely when external network APIs are unreachable or offline.

### Mandatory Disclosure Badges on Every Result Card
Every weather and advisory result card must prominently render:
* **Data Mode Badge:** `LIVE / FORECAST` (Green badge) or `SIMULATED DEMO DATA` (Amber/Dashed badge).
* **Data Provider Attribution:** `Source: Open-Meteo (open-meteo.com)`.
* **Last Updated Timestamp:** Formatted local date and time (e.g., `Updated: 12 Sep 2026, 17:45 IST`).
* **Resolved Location Name & Coordinates:** Resolved geocoding label (e.g., `Pune, Maharashtra, India (18.52°N, 73.85°E)`).

## 5. Weather Fields & API Endpoints

### Primary Open-Meteo Endpoints
* **Geocoding API:** `https://geocoding-api.open-meteo.com/v1/search?name={query}&count=1&language=en&format=json`
* **Forecast API:** `https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}&current=temperature_2m,relative_humidity_2m,weather_code,wind_speed_10m,precipitation&hourly=temperature_2m,relative_humidity_2m,precipitation_probability,precipitation,rain,weather_code,wind_speed_10m&daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_sum,precipitation_probability_max&timezone=auto`

### Required Meteorological Parameters
| Parameter Key | API Field Name | Physical Unit | Description & Agronomic Utility |
| :--- | :--- | :--- | :--- |
| **Ambient Temperature** | `temperature_2m` | °C | Heat-stress and frost detection |
| **Relative Humidity** | `relative_humidity_2m` | % | Fungal disease spore germination risk |
| **Precipitation Probability** | `precipitation_probability` / `precipitation_probability_max` | % | Rain forecast likelihood for scheduling |
| **Precipitation Amount** | `precipitation` / `precipitation_sum` | mm | Expected water depth for drainage & irrigation |
| **Rainfall** | `rain` | mm | Liquid precipitation |
| **Wind Speed** | `wind_speed_10m` | km/h | Spray drift hazard threshold (chemical/nutrient) |
| **Weather Code** | `weather_code` | WMO Code (0–99) | Human-readable sky condition (Clear, Drizzle, Rain, Thunderstorm) |

## 6. Deterministic Advisory Rules & Thresholds

The advisory engine evaluates input variables against explicit threshold rules. Rules execute deterministically and return between 1 and 3 prioritised advisory cards.

```
                  ┌───────────────────────────────┐
                  │ Weather & Farm Context Inputs │
                  └──────────────┬────────────────┘
                                 │
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ Expected Rain    │   │ Wind Speed       │   │ Temperature      │
│ ≥ 20mm (Heavy)   │   │ ≥ 25 km/h        │   │ ≥ 35°C           │
│ OR Rain ≥ 5mm/60%│   │ (Spray Drift)    │   │ (Heat Stress)    │
└────────┬─────────┘   └────────┬─────────┘   └────────┬─────────┘
         │                      │                      │
         └──────────────────────┼──────────────────────┘
                                │
                                ▼
               ┌─────────────────────────────────┐
               │ Relative Humidity ≥ 80%         │
               │ (Fungal Disease Risk)           │
               └────────────────┬────────────────┘
                                │
                                ▼
               ┌─────────────────────────────────┐
               │ Rank & Sort by Priority (1 → 6) │
               │ Return Top 1–3 Action Cards     │
               └─────────────────────────────────┘
```

### Exact Threshold Specifications

#### Rule 1: Heavy Rainfall & Drainage Alert
* **Condition:** $\text{precipitation\_sum} \ge 20\text{ mm}$ OR Any 3-hour forecast sum $\ge 15\text{ mm}$.
* **Advisory Text:** *“Heavy rainfall risk. Check drainage channels, clear field furrows, and avoid field machinery operations in waterlogged areas.”*
* **Category:** Drainage & Flood Risk | **Severity:** High (Red)

#### Rule 2: Irrigation Postponement (Water-Saving)
* **Condition:** $\text{precipitation\_probability\_max} \ge 60\%$ OR $\text{precipitation\_sum} \ge 5\text{ mm}$.
* **Advisory Text:** *“Delay irrigation for 24 hours. Rain is likely and natural precipitation will recharge root-zone moisture.”*
* **Category:** Irrigation Scheduling | **Severity:** Medium (Green/Eco)

#### Rule 3: High Wind & Spray Drift Warning
* **Condition:** $\text{wind\_speed\_10m} \ge 25\text{ km/h}$.
* **Advisory Text:** *“Strong wind expected (≥25 km/h). Avoid foliar pesticide or liquid fertilizer spraying to prevent hazardous spray drift and chemical loss.”*
* **Category:** Chemical & Fertilizer Spraying | **Severity:** High (Amber)

#### Rule 4: Extreme Ambient Heat-Stress Warning
* **Condition:** $\text{temperature\_2m} \ge 35^\circ\text{C}$ OR $\text{temperature\_2m\_max} \ge 38^\circ\text{C}$.
* **Advisory Text:** *“Heat-stress risk is high. Irrigate in early morning or late evening to minimize evaporative loss and inspect crops for canopy wilting.”*
* **Category:** Crop Physiology & Water Stress | **Severity:** Medium (Orange)

#### Rule 5: Pre-Rain Chemical Washoff Prevention
* **Condition:** $\text{precipitation\_probability} \ge 60\%$ AND $\text{precipitation} < 20\text{ mm}$.
* **Advisory Text:** *“Avoid applying foliar pesticides or granular fertilizer immediately before expected rainfall to prevent chemical washoff and soil leaching.”*
* **Category:** Input Protection | **Severity:** Medium (Amber)

#### Rule 6: High Humidity Fungal Pathogen Warning
* **Condition:** $\text{relative\_humidity\_2m} \ge 80\%$.
* **Advisory Text:** *“High atmospheric humidity (≥80%) may increase fungal and bacterial disease pressure. Inspect lower leaf surfaces and avoid prolonged canopy wetness.”*
* **Category:** Disease Prevention | **Severity:** Medium (Purple)

#### Default Rule 7: Routine Optimal Conditions
* **Condition:** Triggered when **none** of Rules 1–6 are activated.
* **Advisory Text:** *“Weather conditions are generally suitable for routine farm activities, weeding, and normal field operations. Continue regular crop scouting.”*
* **Category:** Routine Operations | **Severity:** Info (Blue)

## 7. Advisory Priority Ranking

When multiple atmospheric thresholds trigger simultaneously, advisories are strictly ordered according to farm hazard severity. The top 1 to 3 highest-ranking advisories are displayed to prevent cognitive overload.

| Priority Rank | Trigger Category | Agronomic Rationale | UI Badge Theme |
| :---: | :--- | :--- | :--- |
| **1** | **Heavy Rainfall / Drainage** | Imminent crop drowning, root rot, and soil erosion risk | Red / Danger |
| **2** | **Irrigation Delay** | Direct water conservation and groundwater protection | Green / Water Smart |
| **3** | **Strong Wind / Spray Warning** | Immediate chemical wastage and environmental drift hazard | Amber / Warning |
| **4** | **Heat-Stress Warning** | Rapid transpiration and permanent wilting prevention | Orange / Heat Alert |
| **5** | **High-Humidity Disease Scout** | Latent fungal/spore risk management | Purple / Bio Risk |
| **6** | **Routine Operations** | Confirms standard operational window | Blue / Normal |

## 8. API-Unavailable & Fallback Design

The module implements a strict, transparent failure architecture: **simulated demo data is never masqueraded as live weather**.

```
                           ┌────────────────────────┐
                           │ User Requests Location │
                           └───────────┬────────────┘
                                       │
                                       ▼
                       ┌────────────────────────────────┐
                       │ Fetch from Open-Meteo Endpoints│
                       └───────────────┬────────────────┘
                                       │
                      ┌────────────────┴────────────────┐
                      │                                 │
              [ Success (200 OK) ]             [ Network Failure / 5xx / Timeout ]
                      │                                 │
                      ▼                                 ▼
         ┌─────────────────────────┐       ┌─────────────────────────┐
         │ Render Live Weather     │       │ Check TanStack Query    │
         │ Badge: [LIVE / FORECAST]│       │ Cached Response?        │
         └─────────────────────────┘       └────────────┬────────────┘
                                                        │
                                   ┌────────────────────┴────────────────────┐
                                   │                                         │
                             [ Cached Exists ]                      [ No Cache Available ]
                                   │                                         │
                                   ▼                                         ▼
                     ┌───────────────────────────┐             ┌───────────────────────────┐
                     │ Render Stale Cache Data   │             │ Render Transparent Error: │
                     │ Badge:                    │             │ "Live weather unavailable"│
                     │ [LAST AVAILABLE DATA]     │             │ Button:                   │
                     │ (Shows Exact Timestamp)   │             │ [Use Pune Demo Data]      │
                     └───────────────────────────┘             └─────────────┬─────────────┘
                                                                             │
                                                                             ▼ (If Clicked)
                                                               ┌───────────────────────────┐
                                                               │ Render Offline Demo Data  │
                                                               │ Badge:                    │
                                                               │ [SIMULATED DEMO DATA]     │
                                                               │ (Permanent Warning)       │
                                                               └───────────────────────────┘
```

### Fallback State Rules
1. **Zero Silent Fallback:** The system will **never** silently substitute simulated values without alerting the user.
2. **First-Load Failure:** If Open-Meteo fails and no cached data exists:
   - Display clear state banner: *“Live weather data is currently unavailable. Check your internet connection or try again.”*
   - Display button: `Load Simulated Pune Demo Data`.
3. **Simulated State Appearance:**
   - Permanent top banner: `⚠️ SIMULATED DEMO DATA — For Demonstration Purposes Only`.
   - Data source clearly states: `Simulated Benchmark Scenario (Offline)`.
   - All live claims, real-time indicators, and refresh buttons are clearly disabled.
4. **Cached Live Data:**
   - If prior successful live requests exist in TanStack Query cache:
   - Display data with badge: `LAST AVAILABLE DATA`.
   - Prominently display original capture timestamp: `Captured: 12 Sep 2026, 15:30 IST (Stale)`.

   - High-contrast visual cards featuring category icons (💧 Irrigation, 💨 Spraying, 🌿 Disease, ☀️ Heat).

   - Accordion detailing exact threshold values and priority rankings for 100% agronomic transparency.

## 11. Testing Plan

### Automated Test Specifications (Vitest + React Testing Library)
Tests must run 100% offline with zero external network requests.

1. **API Mocking & Contract Tests:**
   - Mock Open-Meteo geocoding and forecast JSON payloads using Vitest interceptors.
   - Verify correct parsing of temperature, humidity, precipitation, and wind fields.
2. **Location Resolution:**
   - Test successful geocoding resolution for valid query strings.
   - Test graceful error rendering when geocoding returns empty results.
3. **API Timeout & Network Failure:**
   - Simulate `500 Internal Server Error`, `503 Service Unavailable`, and network timeout.
   - Verify that *“Live weather is currently unavailable”* is shown.
   - Verify that clicking *“Use simulated Pune demo data”* activates simulated mode with permanent `SIMULATED DEMO DATA` badge.
4. **Advisory Rule & Boundary Tests:**
   - `Rain prob = 60%`, `Rainfall = 5 mm` $\rightarrow$ Triggers Rule 2 (Delay Irrigation).
   - `Rain prob = 59%`, `Rainfall = 4.9 mm` $\rightarrow$ Does NOT trigger Rule 2.
   - `Wind speed = 25 km/h` $\rightarrow$ Triggers Rule 3 (Spray Warning).
   - `Wind speed = 24.9 km/h` $\rightarrow$ Does NOT trigger Rule 3.
   - `Temperature = 35°C` $\rightarrow$ Triggers Rule 4 (Heat Warning).
   - `Humidity = 80%` $\rightarrow$ Triggers Rule 6 (Disease Warning).
   - All optimal conditions $\rightarrow$ Triggers Rule 7 (Routine Conditions).
5. **Priority Ordering Verification:**
   - Simulate simultaneous `Rainfall = 25 mm`, `Wind = 30 km/h`, `Humidity = 85%`.
   - Verify Rule 1 (Heavy Rain) is displayed at the top, followed by Rule 3 (Wind), capped at max 3 cards.

## 13. Out of Scope

To ensure rapid delivery and stability, the following capabilities are explicitly excluded from Version 1 MVP:

* ❌ Training custom machine learning meteorological prediction models.
* ❌ Automated IoT irrigation valve or solenoid hardware control.
* ❌ Physical soil probe and LoRaWAN sensor hardware integration.
* ❌ SMS, WhatsApp, or Push Notification gateways.
* ❌ Multi-year historical climate analytics and trend regressions.
* ❌ Backend reverse-proxy or microservice routing.
* ❌ Machine learning disease computer-vision inference inside this module.
* ❌ Multi-season crop yield and market price econometric forecasting.
